## High

### H1 — Scrolly e2e races hydration/pin setup
`e2e/beranda.spec.ts:40–55` measures `scrolly.height` immediately after `page.goto("/")`. Before the effect at `delegasi-scrolly.tsx:231` creates the pin-spacer the root is ~1×vh; after pinning it is ~2×vh. If measured early, `pinDistance = height - viewportHeight` is wrong and every `scrollTo(fraction)` lands at the same position, so the `data-active` poll at `:66–80` times out. The `data-state="complete"` check at `:60–64` can pass falsely because that is the initial JSX value (`delegasi-scrolly.tsx:365`).
**Fix**: wait for `.pin-spacer` (or the trigger itself) before measuring, read the trigger's own `start`/`end`, and assert a mid-reveal visual state rather than only the attribute.

### H2 — Pinned stage is taller than the viewport
`delegasi-scrolly.tsx:317` uses `min-h-svh`; title block + padding + logo grid reach ~860–900px at 1280×720, and ~850–950px on a 360×667 phone, while `pin: stage` (`:231`) holds the element fixed. Bottom rail rows and the bottom of the logo stay clipped for the whole reveal; scrolling advances the timeline instead of revealing them. The `gsap.matchMedia` at `:162` only guards reduced motion, not viewport height.
**Fix**: cap the logo panel (`max-h-[calc(100svh-...)]` + `object-contain`), shrink the mobile footprint, or skip pinning on short/narrow viewports (e.g. check `stage.scrollHeight > innerHeight` in `onRefresh`).

### H3 — In-flight tweaks compress the reveal
`eb7249c` halved the pin from 2×vh to 1×vh; `b240d8b` raised Lenis `lerp` from 0.1 to 0.25 (`smooth-scroll.tsx:17`). The six-beat timeline (`delegasi-scrolly.tsx:42–48, 261–293`) now runs over roughly one viewport (~110–120px per beat) and one normal wheel gesture can skip several beats. This defeats the intended "watch the logo build" pacing.
**Fix**: restore ~2–3×vh of pin distance, or reduce beat count / snap between beats; re-test with ~100px wheel deltas after the lerp change.

### H4 — Feature work landed directly on `dev` (standards/process)
`AGENTS.md:5` requires a `feat/<name>` branch cut from `dev` and explicit approval per change. `c603044`, `a272034`, `da044fc`, `eb7249c`, `b240d8b` are feature/fix commits on `dev`. Approval cannot be established from git history.
**Fix**: move the five commits to `feat/home-hero-scrolly` and confirm approval retroactively if required.

## Medium

### M1 — Provider kills every ScrollTrigger globally
`src/components/layout/smooth-scroll.tsx:29–31` iterates `ScrollTrigger.getAll()` and kills all triggers on unmount, including ones owned by `hero-motion.tsx` and `delegasi-scrolly.tsx`. Under Next Fast Refresh the provider remounts while children keep their effects: their triggers are killed and never recreated, so hero parallax and the pinned logo stop working until a full reload. Both children already revert their own GSAP contexts.
**Fix**: delete the loop; let each animation owner revert its own context, or track only triggers created by the provider.

### M2 — Reduced-motion preference is read once in the provider
`smooth-scroll.tsx:11–13` checks `matchMedia(...).matches` on mount only, while `hero-motion.tsx:26` and `delegasi-scrolly.tsx:162` use `gsap.matchMedia` and handle runtime changes. A setting change while the page is open leaves Lenis on/off out of sync with the GSAP animations.
**Fix**: wrap Lenis creation in `gsap.matchMedia().add("(prefers-reduced-motion: no-preference)", …)` with a matching cleanup, or subscribe to `MediaQueryList.change`.

### M3 — Tests miss the two highest-risk provider behaviors
`src/components/layout/__tests__/smooth-scroll.test.tsx:58–63` mocks `getAll()` as `[]`, so the global kill loop is never exercised; there is no StrictMode mount→unmount→mount test for duplicate Lenis/ticker/listeners, and no assertion that `gsap.registerPlugin` ran.
**Fix**: return a fake trigger with a `kill` spy and assert it on unmount; add a `<StrictMode>` test asserting exactly one Lenis instance and one ticker callback; assert plugin registration.

### M4 — Animated logo has no accessible name
`delegasi-scrolly.tsx:369` marks the inline `DelegasiLogo` `aria-hidden="true"` (ignoring its `<title>`), while the only `alt` text sits on the static `<Image className="hidden … motion-reduce:block">`. With motion enabled, screen readers get no logo description.
**Fix**: drop `aria-hidden` on the inline SVG (`role="img"` + `<title>` will name it), or keep the static image in the a11y tree via `sr-only`.

### M5 — `data-state` is misleading and not reset
`delegasi-scrolly.tsx:365` starts at `"complete"` while GSAP immediately sets groups to `opacity: 0`; on a runtime switch to reduced motion, cleanup resets `activeCode` but not `data-state`, so a "building" state can persist above the static fallback. This also weakens the e2e assertion in H1.
**Fix**: initialise `data-state` in the timeline effect (`"building"` with motion enabled) and reset it to `"complete"` in the matchMedia cleanup.

### M6 — Likely first-paint flash of hero copy
`hero-motion.tsx:17–34` creates `gsap.from` in `useEffect`, after the server-rendered opaque H1/subtitle/CTAs have committed. The copy can appear, snap to `opacity: 0`, then animate in.
**Fix**: hide reveal targets pre-hydration (CSS/attribute) and clear it in the effect, or use `useLayoutEffect`/`useGSAP` with an SSR-safe guard.

### M7 — Stale spec and test language
`src/features/home/__tests__/beranda-page.test.tsx:32` is named "…8 faculty chips" although chips were replaced by rail rows (assertions still pass because codes appear once in the desktop rails). `docs/figma-specs/pages/beranda-spec.md:7–8,35` still describes a batik/photo-placeholder hero with three stat cards and a chip row, and lists `heroStats` as required data.
**Fix**: rename the test to match the rail rows; mark the superseded spec sections and data list or update them.

## Low
